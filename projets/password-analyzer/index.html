Password Analyzer

Un mot de passe est-il vraiment solide ? Le projet le mesure de quatre façons : longueur et variété, entropie, attaque par dictionnaire, fuites connues. Essayez-le ci-dessous.

Tout se passe dans votre navigateur. Rien n'est envoyé sur le réseau, rien n'est stocké : ni cookie, ni mémoire locale. Fermez l'onglet et tout disparaît. Pour les tests ci-dessous, évitez quand même de taper un mot de passe que vous utilisez réellement.

L'entropie, pas à pas

        
On regarde quels types de caractères apparaissent : cela donne la taille de l'« alphabet ». Puis entropie = longueur × log₂(taille de l'alphabet).

        
    
          
  • a–z26
    • 
          
  • A–Z26
    • 
          
  • 0–910
    • 
          
  • spéciaux32
    • 
        

        
0 × log₂(0) = 0 bits

        
Limite de la formule : elle suppose des caractères tirés au hasard. « Passw0rd! » affiche beaucoup de bits alors que tout le monde l'essaie en premier. C'est pourquoi les deux autres tests existent.

Fuites : le mot de passe ne part jamais

        
Le projet interroge le service Pwned Passwords en k-anonymat : on calcule l'empreinte SHA-1 du mot de passe, on n'envoie que ses cinq premiers caractères, le service renvoie tous les suffixes qui commencent pareil (plusieurs centaines), et la comparaison du reste se fait chez soi.

        
Ici, rien n'est envoyé : l'empreinte est calculée dans la page et comparée à la liste de démonstration, pour montrer le principe. Ce n'est pas une vraie vérification de fuite.

Comment c'est construit

        
    
          
  • Trois modules Python : main.py (interface console), password_checker.py (règles et entropie), dic_attack.py (dictionnaire et fuites).
    • 
          
  • Les variantes sont dans is_vulnerable_to_common ; l'appel au service est dans check_hibp_password, avec un délai de 3 secondes.
    • 
          
  • Le dictionnaire n'est pas dans le dépôt : le README demande de télécharger rockyou.txt dans un dossier dics.
    • 
        

        
  • Python
  • hashlib
  • requests
  • re

      

      

        
Deux limites, dites franchement

        
    
          
  • Si le service de fuites est injoignable, la fonction répond « non trouvé ». Un résultat rassurant n'est donc pas une preuve quand le réseau manque.
    • 
          
  • Le dépôt contient aussi une fonction slow_hash (PBKDF2, 100 000 itérations) que le script principal n'appelle pas.
    • 
          
  • Les repères de force et le temps estimé affichés plus haut sont des ajouts de cette page, indicatifs. Le dépôt ne donne que le score sur 6.
