Aventure textuelle en Java

Un petit jeu qui se joue dans la console : on donne son nom, on lit des chapitres en appuyant sur Entrée, et la dernière scène dit si l'on a gagné. Un exercice pour se remettre gentiment dans le Java : quatre classes, une liste de scénarios, une méthode récursive.

Projet d'école dans un dépôt privé de l'ESIG (Genève) : le code n'est pas public. La démo ci-dessous est une reconstitution avec mes propres scènes, qui suit le fonctionnement du programme.

Console · Main.main()
Cette démo demande JavaScript. Sans lui, voici le déroulement : bannière de bienvenue, saisie du nom (refusé s'il est vide), quatre scènes séparées par la touche Entrée, puis un message de victoire ou de défaite selon la dernière scène.

La récursion, et la liste qui se vide

La méthode play joue le premier scénario, le retire de la liste, puis s'appelle elle-même avec ce qui reste. Quand la liste est vide, elle s'arrête. Chaque appel reste sur la pile jusqu'à la fin : c'est ce que montre le panneau « Dans la JVM » plus haut.

Piège : removeFirst() modifie la liste reçue. Pour que le jeu garde ses scénarios, Main lui en passe une copie. Le dernier commit du dépôt porte justement ce constat dans son message.

À retenir

  • Valider une saisie avec une boucle : un nom vide ou fait d'espaces est refusé et redemandé.
  • Une récursion a un coût visible : une pile d'appels qui grandit, puis se défait dans l'ordre inverse. Une simple boucle ferait le même travail.
  • Attention aux effets de bord : retirer des éléments d'une liste que l'on a reçue la modifie pour tout le monde.
  • Séparer les rôles : Main démarre, Game orchestre, Scenario raconte, Player représente la personne qui joue.
