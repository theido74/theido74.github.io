Le garde-barrière des flux

Le contenu d'un flux RSS vient d'un site tiers : il n'est jamais cru sur parole. Choisissez un cas, et regardez à quelle étape il passe ou s'arrête. Chaque cas hostile a un test écrit dans le dépôt.

  1. L'adressehttp ou https, sans identifiants, hôte valide, toutes les adresses IP résolues publiques
  2. La connexionvers l'adresse déjà vérifiée, sans nouvelle résolution ; en HTTPS, nom d'hôte et certificat contrôlés
  3. La réponseredirections et erreurs HTTP refusées
  4. La taille10 Mio au plus, mesurés après décompression
  5. Le XMLlu avec defusedxml, déclaration DTD interdite
  6. Les liensseuls les liens http(s) valides sont gardés
  7. Le textele HTML des descriptions devient du texte brut

Comment c'est construit

  • Flask avec une fabrique d'application et un blueprint pour les routes. Les pages sont rendues côté serveur avec Jinja, qui échappe les valeurs.
  • SQLite, avec les clés étrangères activées et des contraintes sur l'espèce et le format des sources. Des commandes Flask initialisent, alimentent et affichent la base.
  • Les requêtes passent par des valeurs liées (?) : l'identifiant reçu n'est jamais collé dans le SQL.
  • Le module RSS sépare deux gestes : télécharger, puis lire. Le premier est strict sur le réseau, le second sur le contenu.
  • 30 tests écrits en trois fichiers : lecture et téléchargement des flux, sources, pages. Les essais HTTPS utilisent un serveur local de test.
