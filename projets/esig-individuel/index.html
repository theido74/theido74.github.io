Prévu, puis retrouvé dans le code

La description fonctionnelle liste trois acteurs et leurs cas d'utilisation. Chacun est tamponné selon ce que le code lu contient. Ouvrez un cas pour voir sur quoi repose le tampon.

8 sur 11 cas prévus retrouvés dans le code, et 4 ajouts hors description.

Caméra IP

  • Fournir un flux vidéoRetrouvé

    Le programme Python ouvre le flux RTSP de la caméra avec OpenCV et lit les images en boucle.

Système

  • Détecter un véhiculeRetrouvé

    YOLOv8 analyse chaque image. Les classes retenues sont voiture, deux-roues, camion, cycliste, piéton, cheval, chien et chat.

  • L'identifierRetrouvé

    Le mode suivi de YOLOv8 donne un identifiant par objet. Une détection n'est enregistrée qu'une fois par identifiant, au passage d'une ligne au milieu de l'image.

  • Calculer la vitesseRetrouvé

    Le déplacement du centre entre deux images, une échelle pixels-mètres fixée dans le code, puis une moyenne glissante sur cinq mesures.

  • Sauvegarder la détectionRetrouvé

    Une photo, un véhicule et une détection (confiance, vitesse) sont écrits dans PostgreSQL. Le modèle relie caméra, véhicule, photo et détection.

  • Garder la photo temporairementRetrouvé, en partie

    Au démarrage du programme, les photos de plus de 24 heures sont supprimées, fichier et ligne en base. La description parlait de 24 à 72 heures ; seul le seuil de 24 heures est dans le code lu.

  • Lire la plaqueNon retrouvé

    Aucune bibliothèque de lecture de plaques dans les dépendances, aucun code de reconnaissance. Le champ « plaque » existe dans le diagramme de classes, pas dans le schéma SQL.

Administrateur

  • Consulter les statistiquesRetrouvé

    Le tableau de bord affiche le nombre de caméras, de véhicules détectés, d'alertes, le taux de confiance moyen et les passages de la dernière heure.

  • Consulter les photosRetrouvé

    Dans la liste des dernières alertes, un clic sur l'identifiant du véhicule ouvre sa photo.

  • Rechercher une plaqueNon retrouvé

    Pas d'écran de recherche dans l'interface lue, et sans lecture de plaque, rien à rechercher.

  • Gérer les camérasNon retrouvé

    La table des caméras existe et une caméra est comptée, mais l'interface n'a pas d'écran pour en ajouter, modifier ou retirer.

Ajouté en route

Absent de la description fonctionnelle, présent dans le code.

  • Alerter par TelegramAjout

    Au-dessus d'un seuil de vitesse, une alerte part sur Telegram avec la photo. Un seuil plus bas marque la détection comme alerte dans le tableau de bord.

  • Gérer les alertesAjout

    Une alerte se supprime, se modifie et se réactive. La suppression est logique : une colonne garde la date.

  • Se connecterAjout

    Un compte administrateur avec mot de passe haché, vérifié par la fonction native de PHP. Accès à l'interface réservé aux comptes connectés.

  • Choisir démo ou réelAjout

    Le mode Démo travaille sur des données déjà capturées, sans caméra. Le mode Réel attend une caméra connectée.

Comment c'est construit

  • Un programme Python découpé en services (détection, suivi, vitesse, photo, comptage, Telegram, base de données) et une interface web PHP, avec des scripts SQL.
  • L'interface lit PostgreSQL par des requêtes préparées. Les valeurs affichées sont échappées.
  • Les réglages sensibles passent par des variables d'environnement. Côté PHP, une bibliothèque installée avec Composer les charge.
  • Un script lanceur crée la base, exécute les scripts SQL et prépare l'environnement Python.

Ce que la comparaison montre

  • Trois cas de la description ne sont pas dans le code lu : la lecture de plaques, leur recherche et la gestion des caméras.
  • Quatre fonctions ne figuraient pas dans la description : alertes Telegram, gestion des alertes, connexion et modes démo et réel.
  • Le dépôt de cours est privé. La version publique, avec une démonstration animée, est sur la page StreetEye.
